## 2. Fix textbook and library URL architecture
The current library generates URLs containing query parameters such as `?type=text_book&book=...`, but subject-level canonical metadata points to `/library/[subjectSlug]` and chapter-level canonical metadata points to `/library/[subjectSlug]/[chapterSlug]`.

Audit whether distinct textbook pages are being incorrectly canonicalized to generic pages. Also inspect whether a generic subject/chapter page combines multiple books' resources while displaying only one book title.

Implement a robust solution so that:

- Each genuinely distinct public textbook/book landing page has a stable, descriptive URL and appropriate unique title, description, and canonical URL.
- Book-specific pages display only the resources belonging to that book.
- Chapter and section pages preserve their intended book context.
- Legacy query-parameter URLs continue working or redirect safely to the corresponding stable URL.
- Query parameters used only for UI filters do not create duplicate indexable pages.
- Invalid slugs, missing content, and ambiguous book names are handled safely.
- Existing internal links, bookmarks, and resource access remain functional.
Prefer stable book-specific routes using the existing data model where practical. Avoid unnecessary database schema changes; if a migration is genuinely required, create a proper migration and document the reason.

## 3. Repair sitemap generation
Audit `src/app/sitemap.ts` for incomplete or duplicate entries.

In particular:

- The current library resource query excludes rows with a null `chapter_id`, potentially omitting general-book resources.
- Queries without pagination may silently omit records when the dataset exceeds the API row limit.
- Ensure every intended public, content-backed book, subject, chapter, and academic landing page is discoverable through the sitemap.
- Exclude empty, invalid, private, unpublished, or otherwise non-indexable pages according to the existing publishing rules.
- Deduplicate URLs and generate absolute URLs from the verified production site origin.
- Handle pagination and database errors explicitly. Do not silently present an incomplete sitemap as a successful complete result.
- Do not add every query-string variation to the sitemap.

## 4. Canonical domain, robots, and metadata
Verify the intended production canonical domain, `https://ilmai.study`, against `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_APP_URL`, current generated metadata, sitemap URLs, and live hostname behavior.

Inspect both `ilmai.study` and `www.ilmai.study`. Ensure one canonical host is selected and the alternative redirects permanently to it at the appropriate infrastructure or application layer. Do not break HTTPS or existing Oracle/Coolify routing.

Review `robots.ts`, page metadata, and actual route output:

- Keep public educational content crawlable and indexable.
- Preserve intentional `noindex` on login, registration, private dashboards, and other non-public pages.
- Do not remove security or authentication protections to improve SEO.
- Correct missing, conflicting, incorrect, or inherited canonical metadata.
- Check for accidental noindex headers, redirects, soft 404s, and empty-content pages.
